

# 简述数据库堆文件的链表和页目录两种组织方式中，空闲空间分别是如何组织的？
在链表方式中，空闲空间通过链表来管理
空闲页链表：维护一个链表，链表中每个节点指向一个完全空闲的页（即页内没有任何有效数据）。
已分配页链表：维护另一个链表，指向已分配但有空闲空间的页。
当需要插入新数据时，系统优先从已分配页链表中查找有空闲空间的页；如果不够用，再从空闲页链表中获取一个新页。

在页目录方式中，维护一个页目录，目录中的每个条目记录了一页的位置及其空闲空间的大小。
页目录是一个数组或哈希表结构，记录了系统中所有页（或其部分页）的空闲空间信息。
当需要插入数据时，系统可以快速定位到有足够空闲空间的页，无需逐页遍历链表。

## 算子4：Projection(S.SNO, CNO, SCORE) —— 投影
```python
class Projection:
    def open():
        child.open()  // 子算子为HashJoin
    
    def next(batch_size=500):
        child_batch = child.next(batch_size)
        if child_batch == EOS: return EOS
        
        // 向量化投影：直接选取所需列
        result_batch = new Batch(capacity=batch_size)
        // 将child_batch中的S.SNO, CNO, SCORE三列复制到result_batch
        result_batch.col_SNO = child_batch.col_SNO
        result_batch.col_CNO = child_batch.col_CNO
        result_batch.col_SCORE = child_batch.col_SCORE
        result_batch.setSize(child_batch.size())
        
        return result_batch
    
    def close():
        child.close()
```
# 画出DBMS缓冲池的结构示意图，并结合缓冲池的内部结构说明一般情况下执行引擎访问数据页面过程。说明其中什么情况下执行引擎读数据页面会触发磁盘页面的写操作？
结构：
$$\begin{array}{|c|}
\hline
页表\\\hline
页面映射、脏标记、引用计数、闩等信息\\\hline
\end{array}\Rightarrow\begin{array}{|c|}
\hline
缓冲池\\\hline
页面1\\\hline
页面3\\\hline
帧3\\\hline
\vdots\\\hline
\end{array}$$
流程：
1. 请求页：执行引擎需要访问某个页（由 `Page ID` 标识），向缓冲池发出请求。
2. 查找页表：缓冲池首先在页表（Page Table） 中查找该页是否已在缓冲池中：
    - 命中（Cache Hit）：该页已在缓冲池中，直接定位到对应帧（Frame）。
    - 未命中（Cache Miss）：该页不在缓冲池中，需要从磁盘加载。
3. 固定页面（Pin）：对该页的固定计数（Pin Count）加1，防止页面被驱逐。
4. 磁盘加载（Cache Miss时）：
    - 缓冲池选择一个空闲帧（或通过替换策略如 LRU/CLOCK 选择一个可驱逐的帧）。
    - 如果选中的帧是脏页（Dirty Page），则先将其写回磁盘（触发写磁盘操作）。
    - 从磁盘读取目标页面到该帧中，更新页表映射。
5. 返回数据：将页面的内存地址返回给执行引擎。
6. 访问完成后解固定（Unpin）：执行引擎完成操作后，调用 `unpin(page_id)` 减少 Pin Count。
7. 标记脏页（可选）：如果引擎修改了页中的数据，标记该页为脏页，以便后续刷盘。

当缓存未命中并且缓存已满，需要驱逐脏页面时会触发磁盘操作
