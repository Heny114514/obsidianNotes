
# 寄存器
## x86-32通用寄存器
- 8个32位寄存器：eax, ebx, ecx, edx, esi, edi, esp, ebp
- 8个16位寄存器：ax, bx, cx, dx, si, di, sp, bp
> 均为对应32位寄存器的低16位
- 8个8位寄存器：ah, al, bh, bl, ch, cl, dh, dl
> 分别为ax-dx的高8位和低9位，h-high，l-low

## x86-64通用寄存器
- 16个64位寄存器：rax, rbx, rcx, rdx, rbp, rsi, rdi, rsp, r8, r9, …, r15
- 16个32位寄存器：eax, ebx, …, esp, r8d, …, r15d
> 分别为对应64位寄存器的低双字(dword)
- 16个16位寄存器：ax, …, sp, r8w, …, r15w
> 分别为对应64位寄存器的最低字(word)
- 20个8位寄存器：al, bl, cl, dl, bpl, sip, dil, spl, r8b, …, r15b, ah, bh, ch, dh
> 前16个寄存器为对应64位寄存器的最低字节(byte)，ah-dh和x86-32相同
> 不能同时使用al-ah, …, dl-dh

## 标志寄存器
### SF(Sign Flag)
运算结果的最高二进制位为1，则SF=1，否则SF=0
### CF(Carry Flag)
运算时最高位向前进位，则CF=1，否则CF=0
### ZF(Zero Flag)
运算结果为0，则ZF=1，否则ZF=0
### OF(Overflow Flag)
加法执行前加数最高二进制位相同，且与结果最高位相反，则OF=1，否则OF=0

# 寻址方式

## 立即寻址（Immediate Addressing）

### 概念

操作数 **直接包含在指令中**，CPU 不需要再访问寄存器或内存。

### 示例

```asm
mov rax, 5
add rbx, 10
```

### 说明

- 操作数是常数
    
- 不需要访问内存
    
- 执行速度快
    


## 寄存器寻址（Register Addressing）

### 概念

操作数 **存放在寄存器中**。

### 示例

```asm
mov rax, rbx
add rax, rcx
```

### 说明

CPU 直接从寄存器读取数据。


### 直接寻址（Direct Addressing）

### 概念

**指令中直接给出操作数所在的内存地址**。

### 示例

```asm
mov rax, [0x600000]
```

### 地址计算

```
EA = 指令中的地址
```

EA = Effective Address（有效地址）

## 寄存器间接寻址（Register Indirect Addressing）

### 概念

**寄存器中存放的是内存地址**。

CPU 通过寄存器中的地址访问内存。

### 示例

```asm
mov rax, [rbx]
```

### 地址计算

```
EA = (RBX)
```

含义：

```
rax = Memory[rbx]
```


## 基址寻址（Base Addressing）

### 概念

使用 **基址寄存器 + 偏移量** 来计算内存地址。

### 地址计算

```
EA = Base + Displacement
```

### 示例

```asm
mov rax, [rbx + 8]
```

### 含义

```
rax = Memory[rbx + 8]
```

### 使用场景

常用于：

- 结构体访问
    
- 栈变量访问
    
- 数据结构
    

## 变址寻址（Indexed Addressing）

### 概念

使用 **变址寄存器 + 位移量** 来计算地址。

### 地址计算

```
EA = Index + Displacement
```

### 示例

```asm
mov rax, [rsi + 16]
```

### 使用场景

主要用于 **数组访问**。

例如：

```c
a[i]
```


## 基址变址寻址（Base + Index Addressing）

### 概念

地址由 **基址寄存器和变址寄存器共同计算**。

### 地址计算

```
EA = Base + Index × Scale + Displacement
```

其中

|参数|含义|
|---|---|
|Base|基址寄存器|
|Index|变址寄存器|
|Scale|比例因子 (1,2,4,8)|
|Displacement|位移|

### 示例

```asm
mov rax, [rbx + rsi*4 + 8]
```

### 说明

```
rax = Memory[rbx + rsi*4 + 8]
```

### 典型用途

数组访问：

```c
int a[10];
a[i]
```

如果 `int = 4字节`

```
地址 = base + i × 4
```


## x86-64 内存寻址统一公式

x86 架构的内存地址几乎都可以表示为：

```
EA = Base + Index × Scale + Displacement
```

说明：

| 元素           | 是否必须    |
| ------------ | ------- |
| Base         | 可选      |
| Index        | 可选      |
| Scale        | 1/2/4/8 |
| Displacement | 可选      |

示例：

```
[rax]
[rax+8]
[rax+rbx]
[rax+rbx*4]
[rax+rbx*4+8]
```


## 总结表

| 寻址方式    | 示例              | 地址计算                  |
| ------- | --------------- | --------------------- |
| 立即寻址    | `mov rax,5`     | 操作数在指令中               |
| 寄存器寻址   | `mov rax,rbx`   | 操作数在寄存器               |
| 直接寻址    | `[0x600000]`    | EA=Address            |
| 寄存器间接寻址 | `[rbx]`         | EA=(RBX)              |
| 基址寻址    | `[rbx+8]`       | Base+Disp             |
| 变址寻址    | `[rsi+16]`      | Index+Disp            |
| 基址变址寻址  | `[rbx+rsi*4+8]` | Base+Index×Scale+Disp |

# 转移指令与分支语句
*(注：以下标志位解释：ZF=零标志，CF=进位标志，SF=符号标志，OF=溢出标志，PF=奇偶标志)*

## 基础比较与辅助指令
这些指令用于设置标志寄存器（EFLAGS），为后续的条件指令提供依据。

*   **CMP (Compare - 比较指令)**
    *   **语法:** `CMP opnd1, opnd2` (如 `CMP EAX, EBX`)
    *   **功能:** 执行隐含的减法操作 `opnd1 - opnd2`，不保存结果，但会根据结果修改标志位（CF, ZF, SF, OF, PF）。
*   **TEST (逻辑比较指令 - 课件Slide 27出现)**
    *   **语法:** `TEST opnd1, opnd2` (如 `TEST ECX, ECX`)
    *   **功能:** 执行按位与（AND）操作，不保存结果，仅修改标志位（常用于判断寄存器是否为0，`TEST reg, reg` 后若结果为0则 ZF=1）。

## 简单条件转移指令 (基于单个标志位)
这类指令仅关注标志寄存器中的某**一个**特定位。如果条件满足，则执行跳转：**目标地址 EIP = 当前 EIP + 相对位移量**。

| 汇编指令 | 含义 | 触发条件 (标志位) | 语法 |
| :--- | :--- | :--- | :--- |
| **JZ / JE** | 结果为零 / 相等则跳转 (Jump if Zero / Equal) | ZF = 1 | `JZ 标号` |
| **JNZ / JNE**| 结果非零 / 不等则跳转 (Jump if Not Zero / Not Equal) | ZF = 0 | `JNZ 标号` |
| **JS** | 结果为负则跳转 (Jump if Sign) | SF = 1 | `JS 标号` |
| **JNS** | 结果为正则跳转 (Jump if Not Sign) | SF = 0 | `JNS 标号` |
| **JO** | 发生溢出则跳转 (Jump if Overflow) | OF = 1 | `JO 标号` |
| **JNO** | 未发生溢出则跳转 (Jump if Not Overflow)| OF = 0 | `JNO 标号` |
| **JC** | 发生进位则跳转 (Jump if Carry) | CF = 1 | `JC 标号` |
| **JNC** | 未发生进位则跳转 (Jump if Not Carry)| CF = 0 | `JNC 标号` |
| **JP / JPE** | 偶数个1则跳转 (Jump if Parity / Parity Even) | PF = 1 | `JP 标号` |
| **JNP / JPO**| 奇数个1则跳转 (Jump if Not Parity / Parity Odd) | PF = 0 | `JNP 标号` |

## 无符号数条件转移指令 (基于组合标志位)
这类指令专用于**无符号整数**（如 C语言的 `unsigned int`）比较后的跳转。
*(专家注：课件Slide 11中对JAE和JB的文字描述由于多加了连词略有不严谨，以下整理在提供课件原意的基础上，标注了严格的架构定义)*

| 汇编指令 | 含义 | 触发条件 (课件/实际标准等价) |
| :--- | :--- | :--- |
| **JA / JNBE** | 高于 / 不低于且不等于则跳转 (Jump if Above) | `CF=0 且 ZF=0` |
| **JAE / JNB** | 高于或等于 / 不低于则跳转 (Jump if Above or Equal) | `CF=0` *(课件注为 CF=0 或 ZF=1，实际严格为CF=0)* |
| **JB / JNAE** | 低于 / 不高于或等于则跳转 (Jump if Below) | `CF=1` *(课件注为 CF=1 且 ZF=0，实际严格为CF=1)*|
| **JBE / JNA** | 低于或等于 / 不高于则跳转 (Jump if Below or Equal)| `CF=1 或 ZF=1` |

## 有符号数条件转移指令 (基于组合标志位)
这类指令专用于**有符号整数**（如 C语言的 `int`）比较后的跳转。由于有符号数存在正负和溢出，因此判断条件是 `SF` 和 `OF` 的关系。

| 汇编指令          | 含义                                        | 触发条件 (课件/实际标准等价)                  |
| :------------ | :---------------------------------------- | :-------------------------------- |
| **JG / JNLE** | 大于 / 不小于且不等于则跳转 (Jump if Greater)         | `SF=OF 且 ZF=0`                    |
| **JGE / JNL** | 大于或等于 / 不小于则跳转 (Jump if Greater or Equal) | `SF=OF` *(课件注带有或ZF=1，实际严格为SF=OF)* |
| **JL / JNGE** | 小于 / 不大于等于则跳转 (Jump if Less)              | `SF≠OF` *(课件注带有且ZF=0，实际严格为SF≠OF)* |
| **JLE / JNG** | 小于或等于 / 不大于则跳转 (Jump if Less or Equal)    | `SF≠OF 或 ZF=1`                    |

## 无条件转移指令
不论标志位如何，强制跳转。

*   **JMP (直接转移)**
    *   **语法:** `JMP 标号`
    *   **功能:** `目标 EIP = 当前 (EIP) + 位移量`。属于相对跳转，优点是可以生成位置无关代码（PIC），节省指令字节数。
*   **JMP (间接转移)**
    *   **语法:** `JMP OPD` (OPD 可以是寄存器 `JMP EBX`，也可以是内存 `JMP DWORD PTR [EBX]`)
    *   **功能:** `目标 EIP = 取出的内容(OPD)`。也就是直接替换 EIP 的值。这是实现 `switch-case` 跳转表、C语言函数指针以及多态（虚函数表）的基石指令。

## 带条件的数据传送指令 (CMOVcc 系列)
这是实现无分支优化（Branchless）的核心指令。它不改变控制流（即不管条件成不成立，EIP都顺序指向下一条指令），而是决定**是否执行数据赋值**。

*   **语法:** `CMOVcc r32, r32/m32` (例如: `CMOVGE EAX, ESI`)
*   **限制:** 目标操作数必须是 32 位/64位寄存器，源操作数可以是寄存器或内存（双字）。不支持8位或16位。
*   **功能:** 如果条件 `cc` 成立，则执行 `(r32/m32) -> r32`；如果条件不成立，则什么也不做（相当于NOP）。
*   **对应指令后缀 (`cc`):** 与跳转指令完全一致。
    *   单标志位: `CMOVE/CMOVZ`, `CMOVC`, `CMOVS`, `CMOVO`, `CMOVP` 等。
    *   无符号数组合: `CMOVA`, `CMOVB`, `CMOVAE`, `CMOVBE` 等。
    *   有符号数组合: `CMOVG`, `CMOVL`, `CMOVGE` (如课件里的), `CMOVLE` 等。

## 条件设置字节指令 (SETcc 系列)
通常用于 C 语言中将布尔比较的结果（`true/false`）实体化为一个数值（`1 或 0`）。

*   **语法:** `SETcc OPD` (例如: `SETG CL`)
*   **限制:** 操作数 `OPD` **必须是一个 8 位（字节）寄存器**（如 `AL`, `CL`, `BL`）或 8 位内存单元。
*   **功能:** 如果条件 `cc` 成立，则将目标操作数置为 `1` (`(opd) <-- 1`)；如果条件不成立，则清零 (`(opd) <-- 0`)。
*   **对应指令后缀 (`cc`):** 同样与跳转指令一致。
    *   单标志位: `SETE/SETZ`, `SETNE/SETNZ`, `SETC`, `SETS`, `SETO`, `SETP` 等。
    *   多标志位: `SETA`, `SETB`, `SETG`, `SETL` 等等。

# 循环指令

## 循环控制方法

### 计数控制（次数已知）
#### 倒计数
将循环次数 n 送入计数器（如 ECX），每循环一次减 1，直到为 0 时结束。
```
mov ecx, 循环次数
loopa:
...
dec ecx
jne loopa
```
#### 正计数
将计数器初始化为 0，每循环一次加 1，并与目标值 n 比较。
```
mov ecx, 0
loopa:
...
inc ecx
cmp ecx, n
jne loopa
```
### 条件控制（次数不固定）
通过特定的测试指令（如 AND、CMP、TEST）检查条件是否成立，决定是继续循环还是退出。
```
例，(AX)中1的个数->CL

mov cl, 0
L:
and ax, ax
jz exit
sal ax, 1
jnc L
inc cl
jmp L
exit:

```

## 80X86 专用循环指令
x86 架构提供了一组专门用于简化循环编写的指令，这些指令通常对标志位没有影响：

| 指令               | 执行逻辑                                 |
| ---------------- | ------------------------------------ |
| LOOP 标号          | (ecx)-1 -> ecx;若(ecx)不为0则跳转。         |
| LOOPE/LOOPZ 标号   | (ecx)-1 -> ecx;若(ecx)不为0且ZF=1跳转。     |
| LOOPNE/LOOPNZ 标号 | (ecx)-1 -> ecx;若(ecx)不为0且ZF=0跳转。     |
| JECXZ 标号         | 若 (ECX) = 0 则跳转。常用于循环开始前防止计数为0导致的错误。 |
注：32位段使用 ECX，16位段使用 CX。

## 循环的编译优化
编译器（如在 Release 模式下）会对循环进行多种优化，以提高执行效率：
### 变量与寄存器绑定
   * 原理：将循环中的频繁访问的变量（如循环变量 i、累加结果 sum）直接存放在寄存器中，而不是内存中。
   * 效果：大幅减少读写内存的操作，减少指令数量。例如将 10 条指令的循环优化为 4 条。
### 循环展开 (Loop Unrolling)
   * 原理：消除循环结构，直接将循环体内的操作重复排列。
   * 效果：消除了跳转指令和计数器维护带来的开销，提高指令流水线的利用率。
### 使用更大寄存器与成组运算 (SIMD)
   * 原理：利用 XMM (SSE) 等 128 位寄存器一次处理多个数据。
   * 示例：在拷贝 20 字节缓冲区时，前 16 字节使用 movups xmm0 一次性完成，剩下 4 字节用通用寄存器拷贝，从而减少循环次数。
### 常量折叠与编译期计算
   * 如果在编译期间就能确定循环的结果，编译器会直接给出结果，而不再生成循环指令。

# 函数调用
## CALL 与 RET 的功能与操作
函数调用的本质是转移指令，即改变指令指针寄存器 `EIP/RIP` 的值，使其按照预定路线执行并返回。

### CALL 指令
*   **功能**：调用子程序，完成执行流的跳转，并保护调用处的断点（下一条指令的地址），以便后续返回。
*   **语法**：
    *   直接调用：`CALL 函数名`
    *   间接调用：`CALL DWORD PTR OPD`
*   **底层操作（CPU执行过程）**：
    1.  **保存断点**：将当前的 `EIP`（即 `CALL` 指令的下一条指令地址）压入堆栈。即 `(EIP) → ↓(ESP)`。
    2.  **跳转程序**：将子程序的入口地址送入 `EIP`，开始执行子程序代码。

### RET 指令
*   **功能**：从子程序返回主程序，恢复执行流。
*   **底层操作**：
    1.  **常规返回 (`RET`)**：从当前栈顶弹出一个双字（保存的断点地址）送给 `EIP`。即 `↑(ESP) → EIP`。**特别注意：执行 `RET` 时，被弹出的栈顶内容必须严格是刚才保存的断点地址，否则程序会崩溃或跑飞。**
    2.  **带参数返回 (`RET n`)**：除了执行上述弹出 `EIP` 的操作外，还会将栈指针加上 `n`（计算方式为 `(ESP) + n → ESP`）。这种方式常用于 `stdcall` 调用约定中，由被调用函数（子程序）自行清理当初主程序压入堆栈的入口参数。

## 函数参数传递的实现
参数传递依赖于操作系统的应用二进制接口 (ABI) 和编译器约定（Calling Convention）。在不同平台和位宽下有较大差异：

### x86 平台 (32位，以 C 语系为例)
*   **传递介质**：主要通过**堆栈 (Stack)** 传递。
*   **压栈顺序**：主程序在执行 `CALL` 之前，将参数从右到左或从左到右压入堆栈（如 `push b`, `push a`）。
*   **读取参数**：子程序通过 `EBP` 寄存器结合正偏移量来读取传入的参数。在标准的栈帧中：
    *   `[ebp + 8]` 是第一个参数（如 `a`）
    *   `[ebp + 0Ch]` 是第二个参数（如 `b`）
*   **栈清理时机**：
    *   `cdecl`（C默认）：由**调用者**（主程序）在 `CALL` 结束后清理，如 `add esp, 8`。
    *   `stdcall`（Windows API等）：由**被调用者**在使用 `RET n` 返回时清理堆栈。

### x64/Linux 平台
*   **传递介质**：优先使用**寄存器**传递参数，以提高效率。栈仅用于参数过多时的后备。
*   **寄存器分配（Linux x86-64规范）**：
    *   前6个整型/指针参数分别使用：`%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8`, `%r9` (如果是32位则为 `edi, esi...`)。
    *   例如：第一个参数传入 `ecx`/`rdi`，第二个参数传入 `edx`/`rsi` 等等。
*   在 x64 中，即便使用寄存器传参，栈中往往也会预留影子空间（Shadow space）。

---

## 断点的保护
"断点"即 `CALL` 指令的直接后继指令地址，保护断点是函数能正确返回的核心。

*   **常规状态下的保护**：
    *   断点地址在 `CALL` 指令执行时被 CPU 自动压入栈区。
    *   在标准的函数序言（Prologue）中，通常会接着执行 `push ebp`（保存原EBP）和 `mov ebp, esp`（建立新栈帧），这使得断点地址被安全地夹在“传入参数”和“原EBP”之间，通过 `EBP` 的保护不受后续栈操作影响。
*   **防范攻击（缓冲区溢出）的保护措施**：
    *   **威胁**：如果局部变量（如字符数组 `char s[10]`）读入过长，溢出可能覆盖掉 `原EBP` 和栈上的 `断点地址`，导致 `RET` 时跳转到恶意代码。
    *   **应对机制（Stack Canaries / 堆栈金丝雀）**：
        *   **增加哨兵**：在局部变量和 `原EBP`（以及断点地址）之间插入一个具有随机性的哨兵值（Security Cookie）。如：`mov eax, dword ptr [__security_cookie]`。
        *   **检测哨兵**：在函数准备返回前，会检测这个哨兵值是否被改变（如 `call @__security_check_cookie@4`）。如果局部变量发生了越界写，必然会先改变哨兵值，此时程序直接报错中止，从而保护了断点不被劫持。

---

## 局部变量的管理
局部变量（Local Variables）的生命周期与函数执行周期强绑定，遵循函数的入栈出栈机理。

*   **空间分配**：
    *   **自动分配**：在函数序言中，通过减小栈指针实现：`sub esp, 4Ch`。此操作一次性为所有局部变量在堆栈上开辟了必要的空间。在 Debug 版本下，往往会多分配一些安全隔离空间（如预留多余的 `40H` 字节缓冲并用 `0xCC` 填充）。
*   **变量寻址**：
    *   通过 `EBP` 结合负偏移量进行访问。例如第一个局部变量存放于 `[ebp - 4]`，第二个位于 `[ebp - 8]`。
*   **生命周期与回收**：
    *   **登场**：进入函数体时，随着 `sub esp, N` 登上舞台。
    *   **退场（空间释放）**：在函数准备返回时（Epilogue），通过 `mov esp, ebp` 瞬间将栈顶指针恢复到局部变量分配前的状态，随后 `pop ebp`。
    *   *注：栈空间的“释放”仅仅是将栈顶指针拔高，**废弃空间中的数据本身并不会被清零或抹除**（内容不变）。因此，C代码中千万不能返回局部变量的指针，因为其内存随时会被下一次函数调用覆盖。*
*   **代码优化（Release与Debug的区别）**：
    *   Debug 版本下严格在栈上分配局部变量。
    *   Release 版本开启编译优化后，编译器可能完全不给局部变量分配内存栈空间，而是直接使用寄存器（如 `eax`, `ecx`）来作为局部变量的载体，甚至整个没副作用的函数都可能被优化掉。未初始化的局部变量在 Release 下由于复用寄存器/旧内存，可能会导致不确定的运行时异常。

## 可重定位目标文件 - ELF格式

### .text代码节
存放程序的可执行机器指令，是整个程序的核心逻辑所在。编译后的所有函数体、控制流代码都在此节中
### .rodata只读数据节
存放只读数据，典型如 C 语言中的字符串字面量（`"hello world"`）、`switch` 跳转表等
### .data数据节
存放**已初始化**的全局变量和静态变量
### .bss未初始化数据节
存放**未初始化**（或初始化为 0）的全局变量和静态变量
### .symtab符号表
记录所有符号（函数、全局变量、静态局部变量、外部符号），包括在.strtab的索引、符号大小等信息
### .strtab字符串表
记录所有符号名的字符串，通过偏移量索引
### .rel.text
记录代码节的相关可重定位信息，代码中对**外部函数调用**、**全局变量地址引用**等需要链接时修正的位置列表
包括需要重定位的信息在目标节的偏移、重定位类型、显示加数（偏移）

### .rel.data
已初始化全局变量中，初始值为**外部函数地址**或**其他全局变量地址**的修正位置列表
## 符号解析
定义三个集合如下：
- **E**：可重定位目标文件集合
- **U**：未定义符号
- **D**：已定义符号

符号解析流程如下：
1. 初始E,U,D为空
2. 遍历输入文件
	1. 若为目标文件：加入E并更新U/D
	2. 若为库文件：匹配U中符号，成功则将其移入D并将库文件加入E
3. 若**D中出现重复**或**U非空**则报错

## 重定位
### 合并节（空间分配）
1. .text：将代码合并并分配连续虚拟地址
2. .data：合并变量并分配地址
3. .bss：为未初始化的静态变量分配地址
4. 为每个符号分配最终运行时地址
### 地址重定位（修正引用）
遍历所有重定位表，根据重定位类型修正地址引用。
重定位类型有两种：
1. (R_386_PC32)**PC相对地址重定位**：重定位值=引用符号地址-(.text地址+r_offset)-重定位位置初始值
2. (R_386_32)**绝对地址重定位**：重定位值=引用符号地址+重定位位置初始值

# 中断与异常
## 异常
指**CPU内部出现**的中断，也称为同步中断。
一条指令的执行过程中，CPU检测到了某种预先定义条件，要终止该指令的执行而产生的一个异常信号，进而调用异常处理程序对该异常进行处理。
### 陷阱

> 陷阱是**有意的异常**，是执行一条指令的结果。它最重要的用途是在用户程序和内核之间提供一个像过程一样的接口，叫做**系统调用**。

- **触发源**：执行特殊指令（如 x86 的 `syscall`、RISC-V 的 `ECALL`）有意触发。
- **同步性**：同步异常——是指令执行的直接产物。
- **返回行为**：处理完成后，控制**总是返回到下一条指令**。
- **典型场景**：
    - 系统调用（`read`、`fork`、`execve`、`exit` 等）
    - 程序调试中的**断点设置**和单步跟踪

> 在 x86 机器中，用于程序调试"断点设置"和单步跟踪的功能就是通过陷阱机制来实现的。

### 故障

> 故障由错误情况引起，它**可能能够被故障处理程序修正**。如果处理程序能够修正错误，就将控制返回到引起故障的指令，**重新执行它**。

- **触发源**：指令执行过程中检测到的可恢复错误。
- **同步性**：同步异常。
- **返回行为**：**可能返回到当前指令**（修正后重新执行），也可能转入 `abort` 终止程序。
- **典型场景**：
    - **缺页异常（Page Fault）**——最经典的故障示例。当指令引用的虚拟地址对应的物理页面不在内存中时触发，缺页处理程序从磁盘加载页面后，重新执行该指令即可正常完成。
    - **除法错误**（除数为 0）——x86-64 异常号 0
    - **数据访问越界**
    - **一般保护故障（段故障/Segfault）**——x86-64 异常号 13
    - 非法操作码、缺段、对齐错误等

### 终止

> 终止是**不可恢复的致命错误**造成的结果，通常是一些硬件错误。终止处理程序**从不将控制返回给应用程序**。

- **触发源**：致命硬件错误（如 DRAM/SRAM 位损坏导致的奇偶校验错误）。
- **同步性**：同步异常。
- **返回行为**：**永不返回**。处理程序将控制返回给 `abort` 例程，由该例程终止应用程序。
- **典型场景**：
    - **机器检查（Machine Check）**——x86-64 异常号 18，在导致故障的指令执行中检测到致命的硬件错误时发生。
    - 控制器出错、存储器校验错等

## 中断
由外设控制器、协处理器等**CPU以外的事件**引起的中断，也成为异步中断。
### 可屏蔽中断
受**标志寄存器IF**控制（IF=0屏蔽）
主要是来自I/O设备的请求

### 不可屏蔽中断
由硬件故障引起：掉电、存贮器错、总线奇偶校验错等。

## 中断描述符表
通过 **IDTR 寄存器**（中断描述符表寄存器）来指定基址和界限，可放在内存任意位置（需 8 字节对齐）。
### 结构与功能

- 同样最多支持 256 个中断/异常向量，但每个表项占 **8 字节**，总计 2KB。
- CPU 获取中断类型号后，通过 **`中断号 × 8 + IDTR基址`** 定位描述符。
- 描述符中不直接存放地址，而是包含 **段选择子 (Segment Selector)** 和 **32 位偏移量 (Offset)**，结合 GDT 间接计算出 ISR 入口地址。

### 三种门描述符

IDT 支持三种入口类型：

|类型|用途|
|---|---|
|**任务门** (Task Gate)|切换到独立任务，包含 TSS 段选择子|
|**中断门** (Interrupt Gate)|处理硬件中断，进入时自动清除 IF 标志（关中断）|
|**陷阱门** (Trap Gate)|处理异常/软中断，进入时**不**清除 IF 标志|

## 中断指令
### 软中断
```
INT n
n为中断类型码0~255
属于内中断

执行流程
FLAGS寄存器入栈
IF=0屏蔽外中断，TF=0禁止单步调试
CS入栈，保存代码段返回地址
IP入栈，保存指令返回地址
从中断向量表获取新地址送入CS，IP
```

### 中断返回
```
IRET

① ↑(SP) → IP 从栈顶弹出指令指针（恢复断点偏移）
② ↑(SP) → CS 弹出代码段寄存器（恢复断点段地址）
③ ↑(SP) → FLAGS 弹出标志寄存器（恢复中断前的标志状态）
```
`IRET` 的一个重要特性是：**中断例程可以在执行期间修改栈中保存的 IP 值**。当 `IRET` 执行时，CPU 会将修改后的 IP 弹出，从而跳转到任意位置继续执行。
